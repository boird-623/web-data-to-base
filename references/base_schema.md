# 统一 Base 字段蓝图

首次创建或修复 Base 前使用本蓝图，并按 `lark-base` 当前规范构造实际命令；创建后必须回读，不得把示例 ID 当真实 ID。

## Base

- 名称：`网页数据采集结果`
- 时区：`Asia/Shanghai`
- 账号表：`账号密码本`

## 账号密码本

推荐字段顺序：

1. `账号标识`：text，主字段；登录目标直接等于账号名，无需登录目标固定为“无需登录”。
2. `网站名称`：text。
3. `登录网址`：text，`style.type=url`。
4. `登录方式`：select，选项为 `account_password`、`none`。
5. `密钥引用ID`：text；稳定非敏感引用，用于更新和去重。
6. `密码状态`：select，选项为`已安全保存`、`缺失`、`密钥库不可用`、`无需密码`；不得出现密码值。
7. `是否启用`：checkbox。
8. `执行顺序`：number，普通整数。
9. `更新时间`：updated_at。

账号记录按 `密钥引用ID` 新增或更新。Base 中禁止创建：密码、验证码、Cookie、Token、会话、秘密值等字段。

## 网址结果表

- 默认名称由 `scripts/base_layout.py site-route --url <登录网址>` 生成，形如 `数据｜example.com`。
- 同一规范化主机只创建一张表；路径、查询参数、片段和 `www.` 不影响分表。
- 第一字段优先使用任务的第一个重复字段，类型 text；若任务没有重复字段，则用 text `记录标识`。
- 任务采集字段按真实语义选择类型，不得全部降级为 text。
- 系统强制补充 `采集账号`、`采集任务`、`采集时间`，用于追踪来源；由运行状态机覆盖写入，不接受页面数据冒充。
- `新增或更新` 时自动把 `采集账号` 纳入重复字段，防止不同账号的相同业务主键互相覆盖。
- 创建后将真实 `table_id` 通过 `base_layout.py bind-site-table` 保存到布局文件。
