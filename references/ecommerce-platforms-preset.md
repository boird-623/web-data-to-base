# 电商多平台数据拉取 · 内置预置规格

> 本文件是 web-data-to-base 技能的预置配方。调用本技能做电商平台数据拉取时，直接按本规格执行：用浏览器打开对应平台页面，按各平台流程用官方「导出 / 下载数据」拉取，**下载到的 Excel 直接发送到对话框交付（当前阶段不新建、不写入飞书多维表格）**。首次部署需完成一次【首次确认】。

## 平台总览

| 平台 | 登录方式 | 拉取范围 | 频率 / 口径 |
|---|---|---|---|
| 海豚智投 | 账号密码（可全自动登录） | 直播场次报表 | 每天，拉前一天 |
| 微信小店电商罗盘 | 微信扫码 | 全选全部店铺 | 每天，拉前一天 |
| 腾讯广告 ADQ 客户工作台 | 微信扫码 | 全选全部广告账户 | 每天，拉前一天 |
| 微信小店（单店主后台） | 微信扫码 | 资金/订单/涉税账单 + 订单管理 + 小店投放 | 财务三块每月初读上月；订单管理/投放默认每天 |

## 首次确认（首次部署一次性收集，逐平台确认）

1. 各平台每天/每月几点执行（默认每天 9:30，Asia/Shanghai；财务三块见第四节）；
2. 海豚智投账号密码（账号为种子预置占位，部署时替换为实际账号；密码已存系统密钥库，确认是否替换）；
3. 罗盘 / ADQ / 微信小店均为微信扫码登录，确认扫码交接方式；登录态失效发提醒；
4. 罗盘 / 微信小店是否全选所有店铺、ADQ 是否全选所有广告账户；
5. 数据最终写入的目标 Excel / 飞书表格及字段映射（可先看数据再提供）；
6. 任何平台失败 / 登录态失效时的通知方式。

## 一、海豚智投（每日直播场次）

- 登录页：https://www.ieh5.com/home/login ；数据页：https://www.ieh5.com/home/live/launch-data/launch-data
- 登录方式：账号 + 密码，无图形验证码、短信、扫码、人脸。
- 账号名随种子预置占位（部署时在配置页替换为实际账号）；密码只保存在本机系统安全存储，登录时通过 `scripts/secure_credentials.py get` 读取。密码不写进技能文件、不随压缩包分发；换电脑或新装后需在该机配置页输入一次密码。
- 数据位置：直播间板块 → 直播投流 → 投放数据 → 顶部「直播场次」标签（默认在计划列表，需切换）。

流程：
1. 打开数据页，未登录则用密钥库中的账号密码登录；切到「直播场次」。
2. 日期选择器点「昨天」。
3. 点「导出」大按钮。
4. **弹窗内日期默认今天，必须单独重选**：点弹窗日历 →「昨天」→ 确定，其余筛选保持全部。
5. 点蓝色「导出」→ 提示「已生成导出任务」，**不会直接下载**。
6. 切到弹窗顶部「导出记录」标签 → 点最新一条「生成成功」的「下载」。
7. 得到「直播场次_YYYYMMDD.xlsx」，每场 1 行、约 39 列。

字段示例：导出文件含消耗、成交金额、整体 ROI、成交订单数、利润、净利润等关键字段，可用于当日口径核对。

## 二、微信小店电商罗盘（每日多店巡检）

- 入口：https://store.weixin.qq.com/compass/patrol
- 登录方式：微信扫码；登录态几天到两周过期，不能自动续期。
- 导出：店铺明细 + 商品明细两类。

流程：
1. 打开入口，失效则请客户扫码。
2. **全选店铺**：打开店铺选择器（默认可能只 1 家带「+N」）→ 点「全选」。⚠️ **第一次点会变全不选，再点一次才全选**。
3. **时间改为昨天单日**：默认「近 7 天」→ 改「自定义」→ 起止都点昨天。
4. **筛选指标只保留 4 项**：成交金额、成交订单数、成交退款金额、退款金额（分别在店铺明细、商品明细设置；商品明细取消成交人数/成交件数，店铺明细取消成交人数/下单金额/下单订单数/下单人数/客单价）。
5. 商品明细点「下载数据」（5 列：商品信息 + 4 指标）；店铺明细点「下载数据」。
6. ⚠️ **店铺明细固定带 4 个体验分列（店铺/商品/物流/服务体验分），筛选不掉，清洗时删除**；商品信息可拆成名称/价格/所属店铺。

口径核对示例：店铺明细与商品明细的成交金额合计应一致，可据此交叉校验。

## 三、腾讯广告（ADQ）客户工作台（每日多账户）

- 入口：https://e.qq.com/ 点右上角「登录 → 我是客户」（登录后以实际工作台地址为准）。
- 登录方式：微信扫码；登录态会过期，不能自动续期。
- 列表页**自带「导出」按钮**。

流程：
1. 打开工作台，失效则请客户扫码。
2. 全选账户（单次最多 50）。
3. 顶部时间设为昨天单日。
4. 点「自定义列」勾选 14 个字段后「确定」（可勾选「保存为常用自定义列」）：
   - 账户信息 5 项：账户（名称）、账户健康度、账户状态、账户运营方、账户是否启用；
   - 指标 9 项：备注、标签、余额、花费、目标转化成本、曝光次数、点击次数、下单金额、下单 ROI。
5. 点「导出」，按当前账户/时间/自定义列导出并下载。

口径：状态类（健康度/状态/运营方/是否启用/备注/标签/余额）取当前值；效果类（花费/目标转化成本/曝光/点击/下单金额/下单 ROI）按昨天统计。

## 四、微信小店（单店主后台）

- 入口：https://store.weixin.qq.com/ 登录进入店铺后台（shop/home，非罗盘、非视频号小店）。
- 登录方式：微信扫码；多店铺场景用右上角「店铺切换器」逐个切换，**数据按店铺隔离**。

### A. 财务三块（资金流水 / 订单流水 / 涉税账单）——每月初读上个月整月

- 位置：资金结算 → 流水与账单 → 资金流水 / 订单流水 / 涉税账单。
- 频率：**每月初读取上个月整月**（非每天）。资金流水把动账时间设为上月 1 日至上月末。
- 资金流水有 T+1 延迟（次日 16 点后看今日数据），月初执行不宜太早（建议每月第 3–5 个工作日，具体首次确认）。
- 提示：单店资金/订单流水条数可能达数千条以上，导出与核对时留意数据量。
- ⚠️ **财务导出强制微信扫码确认，无法自动跳过**。

### B. 订单管理——默认每日

- 位置：订单/配送 → 订单管理（全部订单）。
- 频率默认每天拉昨天，是否改为月度以首次确认为准。

### C. 小店投放 · 直播投放——默认每日

- 位置：营销中心 → 小店推广 → 小店投放 → 直播投放（投放管理/数据分析）。
- 指标：花费、成交金额、实际成交 ROI、成交订单数、直播间观看人数。

### D. 主账号 / 多店 / API 机制

**账号体系（已确认）**：
- **网页层面有"主账号"**：一个管理员微信号扫码后，右上角「店铺切换器」可切换全部店铺，切换本身**不需要重新登录**。
- **API 层面没有"主账号"**：微信小店**每个店独立 AppID**，官方明确"无法通过单一 appid 获取所有小店数据"；自研模式必须逐店拿 AppID/AppSecret（同主体也不通用）。这与罗盘 / ADQ（多账号聚合、一个登录态看全部）本质不同。
- 同一主体（营业执照）最多开 30 家企业店。

**实测步骤（决定是否需要逐店 API）**：
1. 管理员微信扫码登录主账号；
2. 脚本自动切到第 2、3 个店，分别触发财务导出，确认**本次登录内是否只扫一次确认**即可连续导出；
3. 同时在 1 个店拿 1 套 AppID/AppSecret 备用（服务市场 → 经营工具 → 自研）。

**分支决策**：
- 本次登录内切店导出**免扫** → 主账号扫码一次、脚本自动遍历全部店铺，**无需 API**（登录态过期后重扫；财务为月度，频率低）；
- **每店都要扫** → 改用自研 API：逐店拿 AppID/AppSecret（只拿有数据的店，空店跳过），配好后永久自动、不扫码。
- 涉税账单暂无开放 API（见 A）；小店投放（直播投放）属腾讯广告体系，长期 API 走腾讯 Marketing API（developers.e.qq.com）。

## 五、通用健壮性要求（四平台均适用）

1. 执行前先自检登录态：海豚可自动登录；扫码平台失效则发扫码提醒，**不空转、不用空白数据冒充成功**。
2. 一律用平台官方「导出 / 下载数据」，全选店铺/账户后一次导出，不逐页逐个抓取。
3. 下载只认完整文件（.xlsx/.csv），不把 `.crdownload` 等未完成文件当成功。
4. 下载文件须绑定对应平台、账号、任务和时间批次，不只按下载目录最新文件取。
5. 跑完做口径核对：罗盘店铺明细与商品明细成交合计应一致；其余平台核对条数/账户数/关键金额。
6. **交付方式（当前固定规则，严格遵守）**：
   - 当前阶段**不新建、不写入任何飞书多维表格**，导出的 Excel 直接发到对话框交付；
   - **平台导出几个文件就发几个，原样交付，不合并、不拆分、不擅自改动原始导出文件**（不改文件名、不增删工作表、不改动原始数据）；
   - 只执行用户明确点名的筛选/清洗（罗盘按第二节只保留 4 项指标、店铺明细剔除固定的 4 个体验分列）。若另存清洗版，**原始文件必须一并发送，不得只发清洗版，更不得把不同平台或不同明细合并成一个文件**；
   - 每条交付说明写清：平台、明细类型、数据日期、覆盖的店铺/账户数、条数与关键金额，以及任何异常或失败项。

## 六、定时任务与动态调整（随时用自然语言修改）

用户可在调用本技能时直接用自然语言**创建、修改、暂停、恢复或删除**定时任务，无需动配置文件。创建/更新时**读取并遵循 `doubao-cron-scheduler` Skill**，用其 `create_cron_job` / `update_cron_job` / `delete_cron_job` 落地；只有工具调用成功才算生效，不能只回复"我会提醒你"。

**默认计划（首次确认后创建）**：
- 每日任务（海豚直播场次、罗盘多店巡检、ADQ 多账户、微信小店订单管理、小店投放）：默认每天 **09:30**（Asia/Shanghai）拉"昨天"数据；
- 财务三块（资金流水 / 订单流水 / 涉税账单）：每月初拉上月整月；因资金流水 T+1，建议每月**第 3–5 个工作日**执行；
- 各任务可独立设时间，也可合并为一条计划。

**动态修改（直接说，技能自动定位并更新对应任务）**：
- "以后每天早上 9:30 拉数据" → 每日任务改为 09:30；
- "改成每天 10 点"、"财务改到每月 5 号"、"罗盘和 ADQ 暂停几天"、"删掉海豚的定时" → 分别改时间 / 频率 / 启停 / 删除；
- 改完复述最终生效时间（按 cron skill 先 `get_current_time` 校验，明确首次触发是今天还是明天）。

**执行前提（务必向用户讲清）**：
- 定时任务在**电脑开机、豆包处于运行状态**时到点自动执行，无需用户再操作；
- 电脑关机 / 休眠、或豆包未运行时，到点任务**不会触发，标准调度也不自动补跑**；错过当天可手动说一句"拉昨天的数据"补跑；
- 扫码类平台（罗盘 / ADQ / 微信小店）触发时若登录态已过期，任务暂停并发出扫码提醒，扫码后继续，不用空白数据冒充成功。

## 七、持续学习（每次优化都记住）

本技能会持续学习，下次调用更省事，不需要重复教：

- **操作路线变化 / 新坑**：自动写入本机操作配方（新增 `record-step`、修订 `revise-step`、异常 `record-incident`），下次直接回放；
- **需求 / 口径 / 字段 / 范围 / 平台机制的优化**：当场更新进本文件对应章节，并在 `scripts/learnings.py` 学习日志记一条；
- 每次跑完告诉你"本次学到了什么"；你说"看看你都学到了什么"即可查看完整学习日志；
- 注意：配方/学习日志在本机，换机不自动同步；稳定规则已写进本文件、随安装包带走。详细规则见 SKILL.md「持续学习」章节。
