# 下载表格文件导入多维表格

当且仅当用户明确要求“在网页上下载 XLSX/XLS/CSV 并导入多维表格”时启用本流程。不要因为页面存在导出按钮就擅自切换采集模式。

## 任务保存位置

创建或修改任务时统一维护任务级 `保存位置`：目标多维表格、对应多维表格链接、目标数据表、分表规则和来源。

- 用户未指定时，默认 Base 为“网页数据采集结果”，多工作表策略默认为“每个工作表新建数据表”；试运行展示拟建表名。
- 用户明确指定已有 Base、数据表或新建目标时，按用户设置覆盖默认值；正式执行前验证访问权限和结构。
- 用户修改任务时可单独修改保存位置；没有提到保存位置则保留原值。修改只影响后续新计划，不迁移历史数据。
- 自定义目标失效或字段冲突时阻塞当前任务，不得静默退回默认 Base。

推荐任务片段：

```json
{
  "采集模式": "下载文件导入",
  "保存位置": {
    "多维表格": "网页数据采集结果",
    "数据表": "按工作表策略确定",
    "分表规则": "下载文件工作表映射",
    "来源": "默认"
  },
  "文件导入": {
    "支持格式": ["xlsx", "xls", "csv"],
    "工作表": "全部",
    "表头识别": "自动",
    "字段映射": {},
    "多工作表策略": "每个工作表新建数据表",
    "采用内容指纹兜底": false
  }
}
```

## 下载文件绑定

把文件绑定到当前 `网页目标 × 账号 × 任务 × 运行批次`，不能只取下载目录“最新文件”。执行顺序：

1. 触发下载前记录下载目录文件名、大小、修改时间快照和当前批次 ID；
2. 点击导出并记录非敏感配方动作 `trigger_download`；
3. 等待 `.crdownload`、`.part`、`.download` 等临时状态消失，并连续两次观察文件大小稳定；
4. 候选必须是在触发后新建或修改、扩展名为 XLSX/XLS/CSV 的文件；只有一个候选时绑定，多候选时按页面导出名称或用户确认消歧；
5. 记录 `wait_download` 和 `bind_download` 配方步骤，只记录文件名模式、扩展名、大小稳定条件和批次 ID，不记录文件内容；
6. 校验扩展名和魔数。损坏、加密、格式不符或读取失败时阻塞当前计划项，保存断点。

## 解析模块

使用 `scripts/spreadsheet_import.py`。它随 Skill 携带纯 Python XLSX/XLS 依赖，并对 CSV 使用标准库；不执行宏、公式、外部链接或工作簿程序逻辑。

预检所有工作表：

```text
python3 scripts/spreadsheet_import.py inspect --file <下载文件> --mode trial --task-name <任务名> --account-label <账号名> --source-url <来源网址>
```

试运行准备批次：

```text
python3 scripts/spreadsheet_import.py prepare --file <下载文件> --mode trial --target-confirmed --target-base <已确认目标> --output-dir <私有临时目录> ...
```

正式准备批次：

```text
python3 scripts/spreadsheet_import.py prepare --file <下载文件> --mode run --target-confirmed --target-base <已确认目标> --output-dir <私有临时目录> ...
```

可重复的选项：

- `--sheet <名称>`：只导入指定工作表；省略代表全部。
- `--header-rows-json '{"Sheet1":2}'`：用户确认表头行后覆盖自动识别。
- `--field-mapping-json '{"源列":"目标字段"}'`：字段映射。
- `--unique-field <字段>`：可重复，组成唯一键。
- `--content-fingerprint`：仅用户明确同意后，在没有天然唯一字段时使用稳定内容指纹。
- `--table-strategy`：`每个工作表新建数据表`、`逐表指定`、`兼容工作表合并`。
- `--include-summaries`：只有用户明确要求导入合计/小计行时使用。

输出包含 `import_manifest.json` 和逐工作表 JSONL。它们是临时写入载荷，不是用户交付物；写入验证完成后按运行环境的安全临时文件规则处理。

## 多工作表路由

CSV 视为一个逻辑工作表。XLSX/XLS 的每个工作表是独立导入单元：

- 默认：每个工作表写入独立数据表，表名由工作表名安全化得到；
- 逐表指定：用户逐个指定已有数据表或新建表；
- 兼容工作表合并：只有字段名、类型和唯一键兼容且用户明确要求时合并；
- 字段结构不同的工作表不得静默合并。

如果用户只确认 Base 而未确认逐表目标，使用“每个工作表新建数据表”作为简单默认，并在试运行预览中明确展示即将创建的表名。若用户指定一个已有数据表但文件含多个结构不同的工作表，必须再次确认映射。

## 数据识别与风险

- 自动检测前 20 行内的表头；试运行显示实际表头行、字段、类型、有效行数和警告。
- 排除空行、重复表头和“合计/总计/小计/累计”等汇总行；用户明确要求时才能纳入汇总行。
- 重复表头自动加 `_2`、`_3` 后缀，并在试运行提示。
- Excel 中使用纯零格式的编号（例如格式 `000000`）恢复为保留前导零的文本。
- 金额、数量和日期按真实语义保留为 number/datetime；标识符按 text。
- 公式只读取缓存结果，不执行重算；缺少缓存结果时留空并提示。
- 加密、损坏或无法识别的工作簿不尝试破解，阻塞并交给用户处理。

## 新增或更新

- `新增`：分批创建记录，每批最多 200 条。
- `新增或更新`：必须有用户确认的唯一字段；每个工作表独立校验唯一字段是否存在。
- 没有天然唯一字段时，试运行必须要求用户选择唯一字段，或明确同意使用稳定内容指纹；不能无提示反复追加。
- 写入每条记录时补充：`采集账号`、`采集任务`、`采集时间`、`来源网址`、`来源文件`、`来源工作表`、`导入批次`。
- 写入前读取目标表真实字段。缺字段时按预检类型创建并回读；已有字段类型冲突时停止该导入单元，不能把所有值降级为文本。
- `新增或更新` 优先使用多维表格 upsert 能力；如果唯一字段组合需先查询记录，必须分页读取完整匹配范围并串行创建/更新。

## 状态机与断点

下载文件任务阶段为：

`login（如需要） → navigate → filter → download → locate_download → parse_file → write/暂存 → verify → logout（如需要）`

断点至少保存当前下载文件绑定、文件哈希、工作表索引、写入批次和已完成行区间。恢复时先核对文件哈希；文件改变则重新解析，不能沿用旧行游标。多账号连续运行时每个账号必须绑定自己的文件和批次，不能串用。

## 试运行与验证

试运行对每个工作表预览 1 条记录，不写目标 Base；同时展示：

- 文件格式与哈希；
- 工作表、表头行、有效行数、排除行数；
- 字段与推断类型；
- 目标 Base/数据表策略；
- 唯一字段与写入方式；
- 风险和需要用户确认的项目。

正式写入后逐工作表回读，核对：源文件有效行数、准备写入数、新增数、更新数、失败数、唯一字段抽样、来源文件/工作表/批次。任何工作表未验证都不能宣布整次导入完成。
